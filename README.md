# Muse — таск-трекер

Production: [https://musetrack.ru](https://musetrack.ru). FirstVDS, HTTPS и процесс выпуска: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). HTTP по домену и IP перенаправляется на HTTPS.

Репозиторий: `git@github.com:vladSHOKO/Muse.git`. Процесс разработки и GitHub Actions описаны в [CONTRIBUTING.md](CONTRIBUTING.md), выпуск на FirstVDS — в инструкции production выше.

MVP личного таск-трекера на Symfony 7.4 LTS, Twig и PostgreSQL 17. Согласованные требования: [MVP.md](MVP.md).

Интерфейс Muse использует приглушённую пепельно-голубую палитру: светлый серо-голубой фон, мягкие поверхности и сдержанные голубые акценты. Логотип — буква M на светлом пепельно-голубом фоне.

## Возможности

- Регистрация по уникальному email, вход и выход; email регистронезависимый.
- Личные блоки и задачи с простыми чек-листами.
- Рабочее пространство выбранного блока с быстрым переключением и чек-листами прямо в списке.
- Приоритеты задач 1–5: 1 — наивысший; задачи без приоритета идут последними.
- Редактирование названия, текстового описания, состояния и блока задачи.
- Состояния задач «Активна» и «Выполнена»; пункты чек-листа отмечаются независимо.
- Несколько вложений: загрузка, защищённое скачивание и удаление.
- Ссылки только для просмотра, действующие 24 часа, с досрочным отзывом.
- Адаптивный интерфейс на русском языке.

## Котик Muse

Рыжий пиксельный котик живёт на отдельной дорожке над верхним меню: гуляет, сидит, умывается и спит. На узких экранах прогулки короче и реже. Кнопка «Скрыть котика» / «Показать котика» внизу страницы запоминает выбор в браузере. В скрытой вкладке анимация приостанавливается; при уменьшении движения и без JavaScript котик неподвижен (без JavaScript переключатель скрыт). Позиция, направление, текущая анимация и её прогресс сохраняются в sessionStorage для переходов и перезагрузок внутри вкладки. Один клик (или Enter / Space) останавливает котика и оставляет сидеть. Два быстрых нажатия запускают сердечки на четыре секунды, затем возвращается обычное поведение. При уменьшении движения сердечки видны неподвижно. На другой ширине позиция ограничивается краями дорожки.

Графика — пиксельный SVG в `templates/_cat.html.twig`, оформление и поведение — `public/assets/cat.css` и `cat.js`. Внешних библиотек и изменений БД не требуется.

## Требования

- PHP 8.2+; реализация проверяется на PHP 8.4.
- Расширения `pdo_pgsql`, `fileinfo`, `ctype`, `iconv`; стандартные расширения Symfony. Для тестов также нужны `dom`, `xml`, `xmlwriter`, `mbstring`.
- Composer 2, Docker с Docker Compose, Symfony CLI.
- Node.js и сборка frontend для запуска приложения не нужны: CSS и JavaScript находятся в `public/assets`.

## Первый запуск

Из корня проекта:

```bash
composer install
docker compose up -d --wait database
php bin/console doctrine:migrations:migrate --no-interaction
symfony server:start --no-tls --port=8000 --listen-ip=127.0.0.1 -d
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и зарегистрируйтесь. Демо-аккаунты автоматически не создаются.

Локальные параметры подключения уже заданы в `.env`: база `task_tracker`, пользователь и пароль `task_tracker`, порт `55432`. Это настройки локальной разработки. Docker публикует PostgreSQL только на `127.0.0.1`.

Персональные настройки записываются в `.env.local`, который исключён из Git. Перед использованием вне локального окружения необходимо задать собственный `APP_SECRET` и настройки БД; production-деплой не входит в текущую реализацию.

Если порт PostgreSQL занят, задайте `POSTGRES_PORT` в `.env.local` и тот же порт в `DATABASE_URL`, затем запустите Compose с этим файлом:

```bash
docker compose --env-file .env.local up -d --wait database
```

Если Symfony CLI недоступен, для локальной разработки можно использовать встроенный сервер PHP:

```bash
php -d upload_max_filesize=50M -d post_max_size=260M -d max_file_uploads=20 -S 127.0.0.1:8000 -t public
```

Symfony CLI автоматически читает проектный `php.ini`. После изменения PHP-настроек перезапустите локальный сервер.

## Остановка

```bash
symfony server:stop
docker compose stop
```

Данные PostgreSQL сохраняются в именованном Docker volume. Загрузки сохраняются в `var/uploads` на машине с приложением. Удаление volume или этого каталога приводит к потере соответствующих данных.

## Тесты и проверки

Тесты работают с отдельной PostgreSQL БД `task_tracker_test`. Суффикс `_test` автоматически добавляется к имени БД в окружении `test`.

```bash
php bin/console doctrine:database:create --env=test --if-not-exists
php bin/console doctrine:migrations:migrate --env=test --no-interaction
composer test
```

Функциональные тесты очищают таблицы только тестовой БД перед каждым сценарием и используют `var/test-uploads`. Перед очисткой проверяются имя БД и путь хранилища. Не запускайте их параллельно на одной тестовой БД.

```bash
composer validate --strict
php bin/console doctrine:schema:validate
composer check
```

Покрыты регистрация, вход и выход, уникальность email, CRUD, изоляция пользователей, подстановка чужих идентификаторов, CSRF, добавление, изменение и удаление пунктов чек-листа, обратимые и повторные отметки, вложения, граница размера файла, ссылки на задачи, точная граница 24 часов, отзыв и каскадное удаление. Проверки схемы PostgreSQL дополняют проверки модели. Отдельный тест создаёт старую схему в изолированной транзакции и проверяет перенос данных в чек-лист. Текущий набор: 53 теста, 474 проверки, включая встроенное редактирование чек-листа, дедлайны и отдельную вкладку завершённых.

## Правила работы

### Задачи и блоки

Владелец задачи назначается при создании и не меняется. Каждая задача обязательно принадлежит одному собственному блоку. Удаление блока удаляет все его задачи, чек-листы, вложения и ссылки; перед удалением показывается подтверждение. Удаление задачи удаляет её чек-лист, вложения и ссылки.

Название ограничено 200 символами, описание — 50 000 символами. Описание выводится как экранированный обычный текст. Для пароля установлен минимум 12 символов и максимум 72 символа / 72 байта, совместимый с используемым хешированием.

### Дедлайны

Выбор дедлайна: кнопка «Выбрать дату и время» открывает календарь Muse с неделей с понедельника, переключением месяцев, быстрыми датами «Сегодня», «Завтра», «Через неделю» по МСК и временем в формате ЧЧ:ММ (24 часа). «Применить» переносит выбор в форму; задача сохраняется общей кнопкой сохранения. «Без срока» очищает поле. Отмена и Escape не меняют значение; стрелки перемещают фокус по дням, Enter и Space выбирают дату. Без JavaScript и для ручного ввода доступно исходное поле.

Дедлайн необязателен: дата и время с точностью до минуты задаются при создании и редактировании задачи, их можно очистить. Ввод и отображение — по МСК, хранение — в UTC. Незавершённая задача просрочена при `now >= deadline`; выполненная не подсвечивается. Дата и метка «Просрочена» видны в обзоре, списке блока, карточке и публичном просмотре. Состояние просрочки вычисляется при открытии страницы через `ClockInterface`.

Миграция `Version20260913150000` добавляет необязательное поле без изменения существующих задач.

### Приоритеты и выбор блока

Главная страница показывает блоки: до трёх в ряд на широком экране, до двух на среднем и один на мобильном. Неполный ряд занимает всю ширину. В каждом блоке видны до трёх невыполненных задач с наивысшим приоритетом и их полные чек-листы. Задачи можно завершать и открывать для редактирования, пункты — добавлять, отмечать и удалять. Нажмите заголовок блока или «Все задачи», чтобы открыть подробный вид с вкладками «Активные» и «Завершённые» и меню переключения блоков. Главная `/` всегда открывает обзор; `/?block={id}` — активные задачи блока; `/?block={id}&status=completed` — завершённые. Обе вкладки показывают счётчики; кнопка «Открыть снова» возвращает задачу в активные. Правило сортировки одинаково для обеих вкладок.

Раздела «Без блока» нет. Для начала работы создайте блок. Без собственного блока форма создания задачи перенаправляет к созданию блока; сохранить задачу без блока нельзя.

Создание задачи из выбранного блока автоматически подставляет этот блок в форму. После удаления задачи приложение возвращает в её блок; после удаления блока открывается главная страница. Счётчики учитывают задачи выбранного блока; пункты чек-листа в них не входят.

Приоритет необязателен: целое число от 1 до 5, где 1 — наивысший, 5 — наименьший. По умолчанию — без приоритета (NULL). Он задаётся при создании или редактировании задачи. Задачи сортируются от приоритета 1 к 5, затем идут задачи без приоритета; при равных значениях — по дате создания и идентификатору, от новых к старым. Завершённость задачи не меняет эти правила. У пунктов чек-листа приоритета нет.

При обновлении существующей установки примените миграции:

```bash
php bin/console doctrine:migrations:migrate --no-interaction
```

### Чек-листы

Пункт чек-листа (`ChecklistItem`) содержит текст до 200 символов и отметку выполнения и принадлежит задаче. У пункта нет отдельной карточки, описания, файлов, приоритета, блока или ссылки доступа. Создание, изменение текста, отметка, снятие отметки и удаление доступны в карточке задачи, списке выбранного блока и превью на главной. Действия с чек-листом сохраняют исходное представление.

Отметка выполняется кнопкой-галочкой с клавиатурной поддержкой и зачёркивает текст. При наведении или фокусе у пункта появляется карандаш: он заменяет текст полем ввода, а рядом показывает кнопки сохранения и отмены. Изменение сохраняется без перезагрузки; Escape или крестик возвращают прежний текст. После добавления пункта положение формы в окне сохраняется, поэтому технический возврат к чек-листу не вызывает заметного скачка страницы. JavaScript сохраняет отметку без перезагрузки страницы; при его отключении для отметки работают обычные POST-формы с возвратом к чек-листу. Сервер получает желаемое состояние, поэтому повторная отправка запроса не меняет отметку на противоположную. Завершение пунктов и состояние задачи независимы.

Все изменения проверяют владельца и CSRF. Ссылка на задачу показывает актуальные пункты и их отметки только для чтения.

### Обновление прежней модели

Миграция `Version20260913090000` заменяет прежние подзадачи пунктами чек-листа. Названия, порядок и отметки сохраняются. Если у прежней подзадачи было описание, оно переносится в описание задачи; файлы перепривязываются к задаче без изменения физических файлов. При превышении лимита общего описания миграция останавливается до изменений.

Отдельные ссылки на прежние подзадачи удаляются: их перенос на всю задачу расширил бы доступ. Ссылки на сами задачи продолжают работать. Старые карточки подзадач перестают существовать. Для возврата к прежней модели требуется восстановление резервной копии БД; автоматического обратного преобразования нет.

Перед обновлением локальной БД сохранена копия в `var/backups/before-checklists.sql` (не входит в Git).

### Файлы

Лимит одного файла — **50 000 000 байт (50 МБ)**. За один запрос можно загрузить до 5 файлов; число вложений задачи этим не ограничено. Вся пачка валидируется до записи. `max_file_uploads` PHP намеренно выше лимита приложения, чтобы превышение количества приводило к ошибке формы, а не к молчаливому пропуску файлов.

Поддерживаемые расширения: `jpg`, `jpeg`, `png`, `gif`, `webp`, `pdf`, `txt`, `csv`, `doc`, `docx`, `xls`, `xlsx`, `ppt`, `pptx`, `odt`, `ods`, `odp`, `mp4`, `webm`, `mov`. Проверяются расширение и определённый сервером MIME-тип. Предпросмотр и перекодирование не выполняются.

Файлы получают случайные имена и находятся вне `public`. Скачивание всегда выполняется через контроллер с проверкой владельца или действующей ссылки; ответы имеют `Content-Disposition: attachment`, `nosniff` и запрет кеширования.

Удаление метаданных и постановка физического файла в очередь удаления выполняются одной транзакцией БД. Очередь обрабатывается сразу. Если файловая система временно недоступна, файл уже закрыт для скачивания, а удаление можно повторить:

```bash
php bin/console app:files:cleanup
```

При настройке деплоя эту команду следует запускать периодически. Сроки действия share-ссылок от неё не зависят.

### Ссылки доступа

Ссылка на задачу открывает саму задачу, её чек-лист и вложения. Другие задачи и их данные не раскрываются. Отдельных ссылок на пункты чек-листа нет.

Токен содержит 32 случайных байта, представленных 64 hex-символами; в БД хранится SHA-256 хеш. Полный URL показывается сразу после создания и повторно не восстанавливается. В карточке доступны список ссылок, сроки и отзыв. Можно создать несколько независимых ссылок.

Доступ прекращается при `now >= expiresAt` или отзыве. Проверка выполняется при каждом новом запросе, в том числе скачивании. Ответы не кешируются, `Referrer-Policy: no-referrer` предотвращает передачу URL в Referer. Уже начатая передача файла и уже скачанные копии не отзываются.

Ссылка показывает текущее содержимое, включая новые пункты чек-листа, их отметки и файлы. Получатель может переслать её другому человеку. Время хранится в UTC; интерфейс показывает сроки в московском времени с явной пометкой МСК.

## Структура проекта

| Каталог | Назначение |
| --- | --- |
| `src/Entity` | Модель данных и ограничения отношений |
| `src/Controller` | HTTP-сценарии и проверка доступа |
| `src/Form` | Формы и валидация ввода |
| `src/Security` | Вход по нормализованному email и проверка владельца |
| `src/Service` | Файловое хранилище, вложения и временные ссылки |
| `src/Command` | Повторная обработка очереди удаления файлов |
| `src/EventSubscriber` | Заголовки защиты и запрета кеширования |
| `templates` | Twig-шаблоны, включая публичное представление задачи |
| `public/assets` | CSS и JavaScript без сборки |
| `migrations` | Схема БД, ограничения и триггеры целостности |
| `tests` | Модульные и функциональные проверки |

Миграции являются источником схемы. Триггеры PostgreSQL дополнительно запрещают связи с чужими блоками и изменение владельца. Пункты чек-листа связаны с задачей внешним ключом с каскадным удалением. Для обновления БД используйте миграции, а не `doctrine:schema:update`.

### Переход к обязательным блокам

Миграция `Version20260913120000` удаляет прежние задачи без блока (потеря этих локальных данных согласована), требует `task.block_id NOT NULL` и включает каскадное удаление задач при удалении блока. Имена удаляемых файлов записываются в очередь. После миграции выполните `php bin/console app:files:cleanup`. Удаление блока в приложении проходит через `AttachmentManager::deleteBlock`: постановка файлов в очередь и удаление данных атомарны; физические файлы удаляются после фиксации транзакции.

На странице входа ссылка «Создать аккаунт» размещена только под формой; из верхнего меню она убрана.

Создание блоков доступно из общего обзора. Внутри открытого блока кнопки «Новый блок» нет.

Приоритеты 1–5: форма создания и редактирования предлагает пять уровней и «Без приоритета», выбор можно очистить. Миграция `Version20260913180000` сохраняет значения 1–5, остальные заменяет на NULL; задачи и связанные данные сохраняются. Ограничение БД допускает только NULL или 1–5. При откате NULL заменяется на 0; прежние значения вне диапазона не восстанавливаются.

В заголовке открытого блока расположены две кнопки: «Новая задача» и «Изменить блок». В пустом списке задач дублирующей кнопки «Создать задачу» нет.

В форме создания задачи нет поля «Задача выполнена»: новая задача создаётся открытой. В форме редактирования поле сохранено. Встроенная иконка календаря в поле дедлайна скрыта; для выбора используется кнопка «Выбрать дату и время» с календарём Muse, ручной ввод остаётся доступен.

Выбор приоритета оформлен кнопками 1–5: насыщенность пепельно-голубого фона и число заполненных делений уменьшаются от 1 к 5. Подписи шкалы — «Наивысший» и «Наименьший». Выбранная кнопка отмечена рамкой и галочкой; отдельная кнопка «Без приоритета» очищает выбор. Это нативная группа радиокнопок, доступная с клавиатуры и без JavaScript; изменение сохраняется общей кнопкой задачи.

Кнопка «Выбрать дату и время» встроена в правую часть поля дедлайна, на месте прежней нативной иконки. На узких экранах кнопка показана компактной иконкой с доступным названием; она открывает календарь Muse. Ручной ввод и отображение ошибок сохранены.

На главной странице каждый чек-лист можно свернуть и развернуть кнопкой рядом со счётчиком. Сворачиваются пункты и форма добавления; заголовок и счётчик остаются видимыми. Выбор сохраняется отдельно для каждой задачи и пользователя в localStorage текущего браузера и восстанавливается после обновления страницы. В карточке задачи и списке блока чек-листы остаются открытыми. Без JavaScript чек-листы открыты, кнопка скрыта; при недоступном хранилище сворачивание работает без сохранения. Версия assets — `muse-checklist-collapse-1`.

В обзоре блоков на главной секция чек-листа отображается только у задач с пунктами. У задач без пунктов скрыты заголовок, счётчик, сообщение о пустом списке и форма добавления. Первый пункт можно добавить в карточке задачи или внутри блока; после этого чек-лист появляется и в обзоре.

На главной ссылка «Все задачи (N)» показывает количество активных (невыполненных) задач блока, включая задачи за пределами трёх превью. Индикатор в заголовке блока также показывает только активные задачи. Если все задачи завершены, оба счётчика равны нулю.
