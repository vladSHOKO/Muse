# Muse — MVP таск-трекера

Статус: реализовано с учётом перехода к простым чек-листам. Инструкция запуска и проверок: [README.md](README.md).

Репозиторий и процесс разработки: [CONTRIBUTING.md](CONTRIBUTING.md). GitHub Actions проверяет код и поддерживает отдельный ручной workflow выпуска.

Этап публикации начат: FirstVDS для одного пользователя, временный HTTP-доступ по IP по решению владельца. Инструкция и статус: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). Правила задач и регистрации сохраняются.

## 1. Цель и техническая основа

Личный таск-трекер с блоками задач, чек-листами, вложениями и временным доступом по ссылке. Логика данных отделена от отображения для дальнейшего развития представлений.

- Symfony 7.4 LTS, Doctrine и миграции.
- PostgreSQL 17 в Docker Compose с постоянным хранилищем.
- Интерфейс на Twig с CSS и JavaScript без сборки frontend.
- Локальный запуск приложения через Symfony CLI; сервер и production-деплой — отдельный этап.
- Название — **Muse**; приглушённая пепельно-голубая палитра, логотип M.

Рыжий пиксельный котик живёт на отдельной дорожке над верхним меню: гуляет, сидит, умывается и спит. На узких экранах прогулки короче и реже. Кнопка «Скрыть котика» / «Показать котика» внизу страницы запоминает выбор в браузере. В скрытой вкладке анимация приостанавливается; при уменьшении движения и без JavaScript котик неподвижен (без JavaScript переключатель скрыт). Позиция, направление, текущая анимация и её прогресс сохраняются в sessionStorage для переходов и перезагрузок внутри вкладки. Один клик (или Enter / Space) останавливает котика и оставляет сидеть. Два быстрых нажатия запускают сердечки на четыре секунды, затем возвращается обычное поведение. При уменьшении движения сердечки видны неподвижно. На другой ширине позиция ограничивается краями дорожки.

## 2. Модель данных

| Сущность | Поля и связи |
| --- | --- |
| `User` | Уникальный нормализованный email, хеш пароля, дата регистрации |
| `TaskBlock` | Владелец, название, даты создания и изменения |
| `Task` | Владелец, название, описание, состояние, числовой приоритет, необязательный дедлайн с временем, обязательный блок, даты создания и изменения |
| `ChecklistItem` | Задача, текст пункта, отметка выполнения, дата создания |
| `Attachment` | Задача, оригинальное и внутреннее имена файла, MIME-тип, размер, дата загрузки |
| `TaskShareLink` | Задача, хеш токена, время создания и истечения, время отзыва |
| `PendingFileDeletion` | Техническая очередь удаления физических файлов |

Задачи не образуют иерархию. Чек-лист — отдельный набор простых пунктов внутри задачи.

## 3. Регистрация и вход

- Регистрация по email и паролю, без подтверждающего письма.
- Email служит логином и уникален независимо от регистра; уникальность обеспечивается БД.
- Пароли хранятся в виде хеша; вход использует сессии.
- Проверяются email и пароль; формы защищены от CSRF, попытки входа ограничены.
- Пользователь может войти и выйти из аккаунта.

## 4. Задачи, блоки и приоритеты

- Создание, просмотр, редактирование и удаление своих задач и блоков.
- Название обязательно, до 200 символов; описание — необязательный обычный текст, до 50 000 символов.
- Задача имеет состояния «Активна» и «Выполнена».
- Задача обязательно принадлежит одному собственному блоку.
- Приоритет необязателен: целое число от 1 до 5, где 1 — наивысший, 5 — наименьший. По умолчанию — без приоритета (NULL).
- Порядок: 1, 2, 3, 4, 5, затем задачи без приоритета. При равенстве новые задачи отображаются раньше старых; последняя привязка порядка — идентификатор по убыванию.
- Состояние задачи не меняет правила сортировки.
- Дедлайн необязателен: дата и время с точностью до минуты задаются при создании и редактировании задачи, их можно очистить. Ввод и отображение — по МСК, хранение — в UTC. Незавершённая задача просрочена при `now >= deadline`; выполненная не подсвечивается. Дата и метка «Просрочена» видны в обзоре, списке блока, карточке и публичном просмотре. Состояние просрочки вычисляется при открытии страницы через `ClockInterface`.
- Владелец назначается сервером и не изменяется.

Выбор дедлайна: кнопка «Выбрать дату и время» открывает календарь Muse с неделей с понедельника, переключением месяцев, быстрыми датами «Сегодня», «Завтра», «Через неделю» по МСК и временем в формате ЧЧ:ММ (24 часа). «Применить» переносит выбор в форму; задача сохраняется общей кнопкой сохранения. «Без срока» очищает поле. Отмена и Escape не меняют значение; стрелки перемещают фокус по дням, Enter и Space выбирают дату. Без JavaScript и для ручного ввода доступно исходное поле.

## 5. Чек-листы

- Пункт содержит только текст, отметку выполнения и технические данные связи с задачей.
- У пункта нет своей карточки, описания, вложений, приоритета, блока или ссылки доступа.
- Текст обязателен, до 200 символов.
- Пункты можно добавлять, удалять, отмечать выполненными и возвращать в невыполненное состояние.
- Отмеченный пункт визуально зачёркивается.
- Все пункты сразу видны в списке задач выбранного блока и в карточке задачи.
- Отметки сохраняются без перезагрузки страницы; без JavaScript доступны обычные формы.
- Галочки доступны с клавиатуры. Ошибка сохранения не создаёт видимость успешной отметки.
- Повторный запрос с тем же желаемым состоянием не переключает пункт обратно.
- Порядок пунктов — по созданию и идентификатору, от старых к новым.
- Отметки пунктов и состояние задачи независимы.
- Удаление пункта сохраняет задачу, остальные пункты, файлы и ссылки.

## 6. Рабочее пространство

- Главная показывает блоки: до трёх в ряд, неполный ряд растягивается на всю ширину; на узких экранах — два или один.
- Каждый блок показывает до трёх невыполненных задач по приоритету и их полные рабочие чек-листы. Задачи можно завершать и открывать для редактирования.
- Нажатие заголовка блока открывает активные задачи с меню переключения блоков. Завершённые доступны в отдельной вкладке со счётчиком (`status=completed`); их можно открыть снова.
- Раздела «Без блока» нет. Для начала работы необходимо создать блок; задача без блока не сохраняется.
- Главная всегда открывает обзор блоков, без восстановления выбора из сессии.
- Создание задачи из блока предвыбирает этот блок в форме.
- Возврат из карточки и после удаления задачи ведёт в соответствующий блок.
- Счётчики блока учитывают задачи, а не пункты чек-листа.
- У каждого чек-листа показывается количество выполненных пунктов и общее количество.

## 7. Владение и вложения

- Приватные объекты доступны только владельцу; каждое изменение проверяется сервером.
- Подстановка чужого идентификатора не открывает данные и не позволяет изменять их.
- Пункт чек-листа получает владельца через задачу.
- Исключение из приватности — просмотр задачи по действующей ссылке.
- Поддерживаются фото, видео и документы; до 5 файлов за запрос, каждый до **50 000 000 байт (50 МБ)**.
- Проверяются размер, расширение и определённый сервером MIME-тип; список расширений приведён в README.
- Файлы хранятся вне `public` под случайными именами; в БД хранятся метаданные.
- Скачивание идёт через контроллер с проверкой доступа. Постоянных публичных URL нет.
- Можно скачивать и удалять файлы; предпросмотр и перекодирование не требуются.

## 8. Временные ссылки

- Владелец создаёт ссылку на задачу, действующую ровно 24 часа с момента создания.
- Получателю не требуется регистрация; доступ — только просмотр задачи, её чек-листа и скачивание вложений.
- Отдельных ссылок на пункты чек-листа нет.
- Токен криптографически случайный, в БД хранится его хеш.
- Полный URL показывается сразу после создания; позднее можно создать новую ссылку.
- Можно иметь несколько независимых ссылок и отзывать их досрочно.
- При каждом обращении, включая скачивание, проверяются отзыв, срок и область доступа.
- При `now >= expiresAt` доступ прекращается без зависимости от фоновой очистки.
- Ссылка показывает актуальное содержимое задачи, пункты и их отметки.
- Любой обладатель ссылки может передать её дальше. Скачанные копии и уже начатая передача файла не отзываются.
- Время хранится в UTC, интерфейс показывает сроки в МСК. Ответы не кешируются.

## 9. Удаление

- Удаление задачи удаляет её чек-лист, метаданные вложений и ссылки.
- Физические файлы удаляются через надёжную очередь: сразу после удаления метаданных, с возможностью повтора командой `app:files:cleanup`.
- Удаление блока удаляет все его задачи, чек-листы, вложения и ссылки после подтверждения. Файлы удаляются через надёжную очередь.
- Интерфейс показывает последствия удаления.

## 11. Перенос существующих данных

Прежние подзадачи преобразованы в пункты чек-листа. Названия и отметки сохранены; имеющиеся описания переносятся в описание задачи, вложения — к задаче. Старые отдельные ссылки на подзадачи удаляются, чтобы не расширять доступ получателей до всей задачи. Ссылки на сами задачи сохраняются.

Перед миграцией локальной БД сохранена резервная копия `var/backups/before-checklists.sql`. Подробности обновления приведены в README. В активной модели нет отношений между задачами; старые поля существуют только в истории миграций.

## 12. За пределами MVP

- Production-сервер, деплой и настройка резервного копирования по расписанию.
- Подтверждение email и восстановление пароля.
- Совместное редактирование, команды и назначение исполнителей.
- Комментарии, уведомления и история изменений.
- Повторяющиеся задачи и дополнительные состояния.
- Календарь, доска и другие представления.
- Богатый текстовый редактор и предпросмотр вложений.
- Отдельный SPA-клиент и публичный API.

На странице входа ссылка «Создать аккаунт» размещена только под формой; из верхнего меню она убрана.

Создание блоков доступно из общего обзора. Внутри открытого блока кнопки «Новый блок» нет.

Приоритеты 1–5: форма создания и редактирования предлагает пять уровней и «Без приоритета», выбор можно очистить. Миграция `Version20260913180000` сохраняет значения 1–5, остальные заменяет на NULL; задачи и связанные данные сохраняются. Ограничение БД допускает только NULL или 1–5. При откате NULL заменяется на 0; прежние значения вне диапазона не восстанавливаются.

В заголовке открытого блока расположены две кнопки: «Новая задача» и «Изменить блок». В пустом списке задач дублирующей кнопки «Создать задачу» нет.

В форме создания задачи нет поля «Задача выполнена»: новая задача создаётся открытой. В форме редактирования поле сохранено. Встроенная иконка календаря в поле дедлайна скрыта; для выбора используется кнопка «Выбрать дату и время» с календарём Muse, ручной ввод остаётся доступен.

Выбор приоритета оформлен кнопками 1–5: насыщенность пепельно-голубого фона и число заполненных делений уменьшаются от 1 к 5. Подписи шкалы — «Наивысший» и «Наименьший». Выбранная кнопка отмечена рамкой и галочкой; отдельная кнопка «Без приоритета» очищает выбор. Это нативная группа радиокнопок, доступная с клавиатуры и без JavaScript; изменение сохраняется общей кнопкой задачи.

Кнопка «Выбрать дату и время» встроена в правую часть поля дедлайна, на месте прежней нативной иконки. На узких экранах кнопка показана компактной иконкой с доступным названием; она открывает календарь Muse. Ручной ввод и отображение ошибок сохранены.

На главной странице каждый чек-лист можно свернуть и развернуть кнопкой рядом со счётчиком. Сворачиваются пункты и форма добавления; заголовок и счётчик остаются видимыми. Выбор сохраняется отдельно для каждой задачи и пользователя в localStorage текущего браузера и восстанавливается после обновления страницы. В карточке задачи и списке блока чек-листы остаются открытыми. Без JavaScript чек-листы открыты, кнопка скрыта; при недоступном хранилище сворачивание работает без сохранения. Версия assets — `muse-checklist-collapse-1`.

В обзоре блоков на главной секция чек-листа отображается только у задач с пунктами. У задач без пунктов скрыты заголовок, счётчик, сообщение о пустом списке и форма добавления. Первый пункт можно добавить в карточке задачи или внутри блока; после этого чек-лист появляется и в обзоре.

На главной ссылка «Все задачи (N)» показывает количество активных (невыполненных) задач блока, включая задачи за пределами трёх превью. Индикатор в заголовке блока также показывает только активные задачи. Если все задачи завершены, оба счётчика равны нулю.
